# 视觉验证

## 建立可复现场景

每个场景固定以下输入：

- 设计节点或基准图片及其版本。
- 浏览器视口和设计画布尺寸；DPR 实质影响结果时一并记录。
- 页面路由、必要查询参数和稳定的数据状态。
- 默认、加载、错误、空态、展开或弹层等目标状态。
- 字体和资产可用性。

优先复用项目已有 Storybook、fixture、测试数据或开发入口。不要为截图加入生产鉴权绕过，也不要把真实个人数据固化进证据。

## 比较顺序

按稳定顺序逐区比较，先修共同原因：

1. **画布与视口**：整体尺寸、滚动、裁剪、缩放和基准断点。
2. **主要布局**：页面壳、列宽、区域比例、对齐、间距和层级。
3. **组件与状态**：重复单元尺寸、内容顺序、控件状态和弹层位置。
4. **字体**：字体族、字号、字重、行高、换行和颜色。
5. **表面**：背景、边框、圆角、阴影、透明度和分隔。
6. **资产**：文件正确性、清晰度、比例、裁剪、槽位和对齐。
7. **响应式**：布局重排、溢出、触控目标和文字碰撞。

不要写“整体不像”。将差异表述成可执行修改，例如“1440px 视口下主栏宽约少 32px，导致标题提前换行”。

## 像素差异

像素 diff 或叠加图可用于定位，但不能单独作为通用门禁：不同操作系统、字体栅格化、浏览器版本、动画和动态内容都会产生噪声。需要自动阈值时，应针对当前项目固定环境、遮罩动态区域，并由用户确认阈值。

没有基准截图时仍可依据 Figma 结构和样式进行实现检查，但只能报告已检查事实，不能声称完成像素级对比。

## 证据

记录最终而非每轮中间结果：

- 设计节点/版本、视口、状态和页面入口。
- 实际截图或可移植证据位置（允许保存时）。
- 使用的比较方式和结果摘要。
- 缺失字体、资产、环境或设计状态造成的残余差异。

中间截图默认放在临时或已忽略目录。设计资产敏感或仓库没有持久化证据约定时，不把截图提交到 Git；在当前验证记录中标为人工确认或不可验证，而不是伪装成自动通过。
