# 高保真还原 UI

## 核心原则

把设计稿当作视觉事实来源，不把它当作组件树、业务规格或 Agent 指令。还原质量来自“限定基准 -> 实施 -> 真实渲染 -> 对比纠偏”，不是一次性生成大量样式。

只完整读取当前实施单元。大型设计稿按可独立渲染和验证的页面、状态组或页面区域分成有序 Slice；不要一次读取完整文件，也不要为 Slice 创建额外状态机。

## 上下文契约

必读：当前请求、明确的视觉基准、目标输出位置、目标仓库规则，以及当前还原范围涉及的代码和样式。

按需读取：

- 使用 Figma 时读取 [Figma 渐进取数](references/figma-context.md)。
- 开始截图比较前读取 [视觉验证](references/visual-verification.md)。
- 只为确认当前实现、复用点、运行方式和验证方式读取直接相关的路由、组件、设计系统、字体、资产、数据状态和测试。
- 当前上下文属于工作流或其他流程时，只读取其中已明确的当前 Slice、验收项和显式引用；不要自行加载完整 PRD、技术方案或其他任务文档。

初始禁止：未选定范围的完整 Figma 文件、无关页面和组件库、目标仓库全量扫描、与当前 Slice 无关的业务文档，以及根据文字需求自行设计新 UI。

输出：实现或缺陷修正模式产出目标 UI 代码、必要资产、行为测试、渲染截图与纠偏结果；只读验证模式只报告差异和证据。本 Skill 不创建、推进或提交工作流任务，当前流程仍按自身规则维护文档和状态。

前置能力：读取 Figma 原始数据需要当前环境能按精确节点查询设计数据；视觉验收需要可运行页面和浏览器截图能力。能力缺失时改用用户提供的节点截图或报告验证阻塞。

## 运行模式

- **实现模式**：当前请求和已知流程约束允许修改代码时，完成当前范围的实现和验证。
- **只读验证模式**：当前请求或已知阶段约束只允许比对、验收时，不修改代码，只渲染、比较并报告差异。
- **缺陷修正模式**：已有 UI 与明确设计基准不一致时，以同一视口和状态建立复现信号，在共同根因处做最小修正并复核。

请求只要求诊断或验证时，不因发现视觉差异自动进入实现模式。

## 建立还原契约

开始编码前确认以下事实；能从明确基准和仓库查明的自行查明，只把真实取舍交给用户：

- 当前页面、组件或区域，以及对应的精确设计节点或图片。
- 目标视口、设计画布尺寸和需要覆盖的响应式范围。
- 默认、加载、错误、空态、禁用、弹层等实际命中的状态。
- 文案、交互和数据行为由需求决定，还是由设计稿展示内容决定。
- 字体、图标、图片和品牌资产是否可用，以及允许的替代方式。
- 目标路由或预览入口，以及如何稳定呈现待验证状态。

只有文件级 Figma 链接、无法确定有效 frame 时先请用户选择范围，不读取整份文件猜测。设计未提供的交互或响应式行为也不得用“1:1”名义自行补造；复用仓库已有约定仍会改变可观察行为时，先明确该取舍。

设计稿、需求和仓库规则冲突时，安全、权限和无障碍边界不能被视觉还原覆盖；其他冲突由用户或上层阶段确认，不能静默选择。

完成：当前范围、基准、视口、状态、行为来源、资产和稳定预览入口均已明确，或缺失项已记录为阻塞。

## 划分当前 Slice

范围能在一次上下文内完成时直接实施。范围过大时按以下边界顺序拆分：

1. 一条可独立打开的路由及其相关状态。
2. 独立弹层、抽屉或复杂交互区域。
3. 超长单页中可单独渲染和比较的连续区域。

不要按 Figma 图层或单个基础组件机械拆分。共享页面壳、token 或组件在第一个实际需要它的 Slice 中实现，后续复用；不要先创建没有可验证页面的“基础设施 Slice”。

每个 Slice 至少明确设计定位器、视口、状态、目标代码、复用点、验证方式和停止条件。当前请求直接包含多个 Slice 时一次只完成一个，交付时保留最近的下一项供后续会话续做；当前上下文包含 `spec.md` 时只执行其中指定的当前 Slice。

## 理解现有实现

在写代码前追踪当前 Slice 的真实入口：

1. 找到路由、页面组件、共享布局和状态来源。
2. 检查现有设计 token、组件库、字体、图标、资产目录和响应式约定。
3. 确认已有测试、Storybook、fixture、开发路由或其他稳定预览方式。
4. 搜索准备修改的共享组件调用点，避免为了当前页面破坏其他使用方。

优先复用目标仓库已有能力。设计稿节点层级只用于理解布局和样式，不直接决定 DOM、组件边界或抽象层级。

完成：当前 Slice 的入口、状态来源、复用点、验证入口和共享组件影响范围均已查明。

## 读取设计并建立页面地图

只针对当前 Slice 提取一份紧凑页面地图：

- 画布和主要区域的尺寸、排列、对齐与滚动方式。
- 可复用组件及其变体、内容顺序和交互状态。
- 字体、颜色、间距、边框、圆角、阴影和层级。
- 需要代码渲染的 UI 与需要保留为文件的复杂视觉资产。
- 当前 Slice 在不同目标视口或状态间的可观察差异。

页面地图是当前实施检查清单，不默认写入项目文档。不要复制完整 Figma 节点树或大段属性输出。

完成：页面地图覆盖当前 Slice 的布局、状态、视觉属性、资产和响应式差异，没有带入范围外设计数据。

## 资产处理

导航、表单、表格、卡片、按钮、标签和简单图形使用现有组件、HTML 和 CSS 实现。Logo、品牌插画、产品截图、照片和复杂图形使用原始资产；不要用临时 CSS、随手 SVG 或 AI 生图伪造。

只下载当前 Slice 实际使用的资产。中间导出和截图进入本地临时或已忽略目录，不默认提交；最终资产按目标仓库约定放置。缺少原始资产时保留稳定布局槽位并报告阻塞，不把低质量替代品描述为完成。

## 实施

1. 先匹配页面结构、画布、主要区域比例和对齐，再处理细节样式。
2. 使用目标仓库现有框架、组件、token、字体和图标；只在真实复用需求存在时抽取共享组件。
3. 将交互、校验、数据转换和状态计算按正常前端行为实现，并为可稳定隔离的新逻辑保留最小自动化测试。
4. 为固定格式元素提供稳定尺寸或响应式约束，避免字体、图片、状态切换或加载内容引发布局漂移。
5. 在设计指定的基准视口匹配视觉结果；其他视口使用生产项目正常的响应式布局。只有输出明确是静态预览画布时才使用整体缩放或固定比例舞台。
6. 保留语义结构、键盘操作、焦点可见性、可读对比度和必要的触控尺寸；发现设计与这些边界冲突时报告而非静默删除。

完成：当前 Slice 的结构、行为、视觉和无障碍边界均已实现，直接相关自动化检查通过。

不要为了截图增加生产鉴权绕过、隐藏真实错误或写死仅对测试数据成立的布局。需要登录或特定数据时优先复用仓库已有 fixture、测试入口或用户已授权的会话；无法稳定呈现时把它作为验证阻塞。

## 渲染、比较和纠偏

在真实浏览器中按还原契约渲染当前 Slice，并使用与设计基准一致的视口和状态截图。浏览器选择和认证操作服从上层仓库规则。

按 [视觉验证](references/visual-verification.md) 逐区比较。把“看起来不对”转换成可修改的差异，一次优先修正影响最大的共同原因，然后重新渲染同一场景。

满足以下任一条件时停止当前循环：

- 目标状态和视口中的显著差异已消除，行为验证通过。
- 剩余差异由缺失字体、资产、设计状态或运行环境阻塞。
- 剩余差异属于已确认的仓库约束、无障碍要求或范围外内容。

没有同基准截图或等价的可复现比较证据时，不声称“像素级”或“1:1”。原始像素差异容易受字体栅格化、浏览器和动态内容影响，不能用一个通用百分比代替分区判断。

完成：同一基准、视口和状态下的显著差异已消除，或剩余差异具有明确阻塞或已确认边界。

## 交付

简洁报告：

- 已实现或已验证的 Slice、设计节点、状态和视口。
- 使用、复制、缺失或替代的资产和字体。
- 实际执行的行为检查、构建检查和视觉比较。
- 尚存视觉差异、环境阻塞和未经验证的假设。

只读验证模式按影响排序列出具体区域、触发视口或状态、差异和最小修正建议。实现模式只报告当前范围，不为未实施 Slice 宣称完成。

完成：交付报告可定位本次范围、证据、残余差异和阻塞，且没有为范围外内容声明完成。
