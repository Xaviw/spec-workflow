# 生成工作交接提示词

## 上下文契约

必读：`AGENTS.md`、当前请求、当前对话和本 Skill。

按需读取：用户或当前对话已唯一选定的 `task.json`、当前阶段产物和 `node tools/workflow.js task status <task> --json` 输出；当前工作涉及的目标仓库 Git 状态、差异摘要和验证结果。

初始禁止：搜索候选任务、读取其他任务或全部迭代、批量加载项目长期记忆、探索无关源码，以及读取或输出凭据值。

输出：一个可直接粘贴到新会话的交接提示词。除非用户明确指定保存路径，否则不创建或修改任何文件；不得借交接推进阶段、提交代码或改写任务产物。

## 确定交接类型

1. 先采用当前对话已经确认的工作类型，不重新路由任务。
2. 用户已给出 task ID、路径、链接，或本轮已唯一选定 task 时，按 **task** 交接。不得从脏工作区或候选任务猜测活动 task。
3. 本轮已确认走 `sw-simple-change`，或已明确不创建工作流 task 且工作仍是一个局部变更时，按 **simple-change** 交接。
4. 现有事实无法支持唯一分类时，先请用户明确 task 或 simple-change；不要调用 `sw-route-task` 代替用户选择。

用户附带的参数描述新会话重点；只调整交接内容的详略和下一步，不改变已经确认的工作类型。

## 收集续做证据

### Task

1. 运行 `node tools/workflow.js task status <task> --json`，记录 task 根相对路径、phase、当前阶段产物是否存在、下一阶段和 baseline/final Git 快照。
2. 只在判断进度和下一步所需时读取当前阶段产物、`decisions.md` 及其显式引用；交接中引用实际路径，不复制规格、ADR、提交或 diff 已保存的内容。
3. 根据当前对话和仓库现场区分已完成、进行中、未开始与来源不明的修改。保留用户修改，不把脏文件自动归入本 task。
4. 按 `AGENTS.md` 的 phase 路由给出下一会话应调用的唯一阶段 Skill；终态 task 只说明现状，不建议隐式重开。

### Simple-Change

1. 记录原始目标、完成标准、目标仓库、分支、已知基线，以及当前 Git 状态和直接相关差异摘要；来源不明的修改明确标为待核对。
2. 记录已经执行的命令及其结果、尚未执行的验证、审查或提交步骤，以及最近一个可直接执行的下一步。
3. 建议下一会话调用 `sw-simple-change` 续做，并说明当前位于修改、验证、审查还是提交确认环节；若现场已不满足简单变更硬门禁，标明应重新路由，不擅自升级。

## 输出要求

对敏感信息脱敏：只保留环境变量名、配置来源和获取方式；不得输出令牌、口令、私钥、完整个人敏感信息或其他凭据值。

默认仅输出一个 Markdown 代码块，不添加前言。提示词使用简体中文，并包含：

- 工作目录、交接类型和 task 路径或目标仓库；
- 目标与可验证完成标准；
- 已完成、当前现场和未完成事项；
- 按执行顺序排列的下一步，第一步可立即执行；
- 已确认决定、显式未决项、阻塞和不可违反的边界；
- 已有产物、相关 diff 或提交、验证证据的路径或命令；
- “建议调用的 Skills”，只列续做直接需要的 Skill 及调用时机。

提示新会话先读取 `AGENTS.md`、重新核对 Git 与 task 状态，再继续工作；不要把交接中的现场信息当作不会变化的事实。
