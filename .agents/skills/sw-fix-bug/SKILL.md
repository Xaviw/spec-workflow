# 修复 Bug

## 上下文契约

必读：用户报告的现象和预期行为。

按需读取：定位仓库或环境需要的 `AGENTS.local.md`；`node tools/workflow.js task list --json` 返回的任务元数据；用户选定任务的状态、验收标准、`spec.md`、Git 快照和验证记录；相关仓库说明、目标代码、调用点、测试及适用规范。

初始禁止：全部任务正文、无关项目知识、无关仓库源码，以及尚未明确修复范围时的代码修改。

输出：可复现证据、根因、最小修复、验证和代码审查结论；关联任务时同步受影响证据，未关联任务时不修改工作流文档。

## 边界

- 不判断简单或复杂任务，不为 Bug 创建新任务。只判断问题是否属于已有 task，以及它是否真是“实现偏离已确认预期”。
- 预期行为不明确，或修复要求改变业务规则、公共契约、数据模型或安全决定时，停止修复并交回当前任务阶段或 `sw-route-task`，不得把需求变化伪装成 Bug。
- 用户只要求诊断、排查或解释原因时，在报告根因和证据后停止，不修改代码或文档。

## 关联任务

1. 用户已明确 task 时，运行 `task status <task> --json`，不搜索候选。完成：关联范围和阶段已知。
2. 未明确 task 时运行 `task list --json`，根据仓库、标题和阶段筛选最多 5 个真实相关项，让用户选择一个或“不关联任务”；不得自动关联。没有合理候选时直接按不关联处理。完成：本次修复是否同步任务已由用户决定。
3. 仅在用户要求修复时处理阶段：`implementation` 任务直接承接；`verification` 任务保持当前阶段，修复后重新执行验证；done 任务仅在迭代开放、各仓库当前 HEAD 仍等于 final 快照、预期未变化且用户确认时运行 `task reopen <task> --confirmed`，固定恢复到 verification。已收口迭代或仓库已前进的 task 只作只读上下文。早于 implementation 的任务交回当前阶段处理，cancelled 任务不承接修复。完成：没有吸收无关提交或修改已封存记录。

不关联任务时只修改目标代码仓库，不更新任务文档、项目长期记忆或 iteration simple change 记录。

## 建立反馈信号

1. 记录目标仓库的 branch、HEAD 和脏文件；重叠修改交由用户决定，不 stash、reset、checkout 或建分支。完成：修复和审查基线明确。
2. 明确实际现象、已确认预期、触发条件、环境和频率，建立能判定该症状的最小反馈信号。依次优先复用失败测试、聚焦命令、API/CLI 调用、浏览器检查、请求或日志回放、性能基线；布局、动画、复杂交互和无法自动化的环境可使用截图或结构化人工步骤。现象是与 Figma、设计稿截图或其他明确视觉基准不一致时，调用 `ui-recreate` 的只读验证模式，以精确节点或图片、版本、视口和状态建立原始视觉信号。完成：信号命中用户报告的同一问题，而不是邻近失败。
3. 运行并按需最小化复现。偶发问题记录重复次数和复现率；性能问题先记录可比较基线。无法获得可信信号时列出已尝试方式和所需日志、HAR、转储、录屏或环境访问，停止推测性修复。完成：问题已复现，或已明确证据不足。

## 定位和修复

1. 根因明显时直接验证；存在多个合理原因时列出可证伪的排序假设，一次只改变一个变量。临时日志使用唯一 `[DEBUG-<id>]` 前缀，性能问题优先使用测量、profile 或二分。完成：根因有反馈信号或代码路径证据支撑。
2. 修改前搜索目标符号的调用方和同类路径，在共同根因处完成最小修复，不补单个症状、不顺手重构。修复目标本身是视觉还原偏差时，定位根因后调用 `ui-recreate` 的缺陷修正模式完成当前明确范围的实现与同基准纠偏；本 Skill 仍负责关联任务、文档同步、测试和代码审查。完成：已知受影响路径得到一致处理。
3. 有正确公开测试接缝时，优先把最小复现转为有效 red，再写使其 green 的最小实现；用户可一次性选择测试后补或替代验证。没有正确接缝时保留原始反馈信号并说明限制，不编写提供虚假信心的浅层测试。完成：修复前后的信号能够区分目标行为。
4. 重跑最小复现和原始场景，执行直接相关测试及适用的类型、lint 或构建检查；只在最后运行一次适用的全量检查。删除临时日志和一次性诊断代码。完成：原始症状不再出现且没有遗留诊断改动。
5. 以关联 task 的 baseline Git 快照或步骤 1 的 `HEAD -> worktree` 为范围调用 `code-review`，要求报告列出实际读取的专项参考、原始触发场景和修复后复核结果，由本 Skill 处理发现并在修改后复审。完成：P0/P1 已按调用方门禁处置，原始问题已用同一反馈信号复核，最终范围无阻塞。

## 同步和交付

- 关联任务时只更新因修复而失真的当前任务文档和验证证据；`implementation` 任务修复后交回 `sw-implement` 完成阶段收尾，`verification` 或由 done 重开的任务直接调用 `sw-verify` 重新验收，不在本 Skill 内提交。修复证明上游预期或方案错误时，先更新并重新确认受影响文档。
- 未关联任务时不写工作流文档；验证和复审完成后给出目标仓库提交计划和完整 message，取得一次确认后提交。
- 完成后提示：`修复及可执行验证已完成，请继续业务自测；若仍发现缺陷，直接说明现象或再次调用 sw-fix-bug。`
