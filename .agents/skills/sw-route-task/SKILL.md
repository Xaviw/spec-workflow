# 路由开发请求

## 上下文契约

按需读取：术语或项目范围不清时读取 `CONTEXT.md`、`project/index.md`；运行 CLI 或定位仓库确有需要时读取 `AGENTS.local.md`；候选判断使用 `node tools/workflow.js task list --json` 返回的开放任务元数据，只有初判可能相关时才读取对应 `prd.md`。

初始禁止：所有任务正文、全部迭代、全部项目知识、目标仓库源码。

输出：命中时返回任务分类、最多 5 个相关任务候选及一个合并后的用户选择问题；未命中时退出本 Skill 并直接处理原请求。

## 流程

1. 确认请求明确要求新增或修改目标项目交付物，且不是只读询问、解释、探索、比较、评估、状态查询、本工作流机制自身维护或显式其他 Skill 请求。未通过时退出本 Skill，直接处理原请求且不运行任务或迭代 CLI。用户以问句提出变更仍属于变更请求；探索若只是已授权交付中的一个步骤，仍随该变更处理。完成：非开发交付请求已离开通用路由。
2. 检查请求是否为现有行为的报错、失败、异常、回归、性能下降或偶发问题。若是，交给 `sw-fix-bug`，不分类、不创建任务。完成：Bug 请求已离开通用开发路由。
3. 检查用户是否已明确要求继续、修改或交付某个工作流任务，并给出任务 ID、路径、链接、唯一名称，或本轮已选定唯一任务。若是，读取其 `task.json`，运行 `task status <task> --json` 并按阶段路由，不搜索候选。仅提供任务引用不代表授权推进。完成：已交给唯一的阶段 Skill。
4. 否则同时判断任务规模和相关任务。仅在需要统一术语或识别项目范围时读取对应入口；运行 `task list --json`，先按以下硬门禁分类，再从 CLI 返回的开放任务中筛选最多 5 个真正相关项。完成：得到一个分类结论和 0-5 个候选。
5. 只要选择中可能出现“独立简单变更”或“新建任务”，就在同一轮运行 `iteration list --status open --json`，把已有开放迭代和“新建迭代”并入同一个选择问题。用户选定已有任务后立即运行 `task status <task> --json`；选定新迭代时由 Agent 使用用户确认的标题运行 `iteration create`，随后创建任务或交给 `sw-simple-change`。新任务只用 `task create` 建立最小状态，再调用 `sw-prd` 创建文档。完成：一次选择后直接进入 `sw-simple-change`、唯一现有任务的阶段 Skill，或新任务的 PRD 阶段。

不持久化活动任务；新会话中的未提交目录不代表用户已选择任务。

## 分类门禁

仅当以下条件全部满足时成立：

- 要求和验证方式清楚；
- 只涉及一个仓库中的局部模块；
- 一次上下文可完成；
- 不涉及数据库结构或迁移、安全或权限、公共契约、生产环境、不可逆操作。

不满足任一项则推荐工作流任务。用户可对工作量、跨仓库或一般不确定性选择降级，但不得绕过硬门禁。

## 候选判断

运行 `task list --json`。CLI 只返回开放迭代中的非终态任务及其路径、标题、阶段和仓库，不按时间、作者或提交历史猜测相关性。

CLI 不接收需求文本，不做语义相关性或 Top 5 截断。根据用户请求判断相关性；作者邮箱只作线索，元数据不足时只读取疑似相关任务的 PRD。不得自动关联。

## 选择分支

- 简单任务且存在相关任务：询问“同步到候选任务”或“作为独立简单变更”。
- 工作流任务且存在相关任务：询问“继续候选任务”或“新建任务”。
- 独立简单变更或新建任务：在同一轮要求选择已有开放迭代或新建迭代；没有开放迭代时只需确认建议的新迭代标题。
- 没有候选：简短说明分类结论，并在需要记录新工作时同时完成迭代选择。

若用户选择同步到工作流任务，必须遵守该任务当前阶段，不得走简单任务捷径。

用户要求取消任务时，确认目标后运行 `task cancel <task> --confirmed`。工作流不物理删除任务；不得主动标记取消。
