# 技术方案写作参考

## 写作原则

- 单任务方案服务于内部追踪和后续实施，允许精确引用上游文档和技术证据；迭代总方案服务于外部评审，必须将引用转换成必要事实和结论。
- 只写当前证据和已确认需求能够支持的内容。信息不足但不影响方案成立时留空或省略；影响核心设计、安全、数据正确性或验收时列为待确认问题。
- 明确区分当前状态与目标状态，说明变化及其影响。单任务方案可记录取证位置，迭代总方案不记录。
- 只保留与本次变化相关的内容。专项检查未命中时不写检查过程或“不适用”。

## 单任务方案

- **设计范围与依据**：引用需求、决定、ADR、项目事实和必要调研，写明涉及仓库或模块。引用实际文件路径；代码证据优先使用 `repo-id:path#symbol`，只有符号不足以定位时才加行号。
- **当前实现**：简述与本次变化直接相关的入口、调用链、数据来源、约束和复用点，并附证据定位；不要复制源码或上游文档正文。
- **目标设计**：按下方章节指引写完整设计结论。引用可以证明为什么这样设计，但不能替代接口、字段、状态、DDL、安全和异常约定。
- **发布与验证**：写明实施顺序、依赖、迁移、回滚和测试策略；可引用已有标准或 artifact，但把本次具体动作写清楚。
- **风险与待确认问题**：记录真实风险和阻塞问题；缺少但不影响设计的信息可以留空。
- **验收覆盖**：逐项列出 AC ID 及其设计落点，保证后续实施方案能建立稳定映射。

## 目标设计与迭代总方案章节指引

### 概述

- **方案背景**：用最少文字说明要解决的问题、需求来源和当前主要限制。没有新增信息时保持简短。
- **实现目标**：描述技术方案交付后的可观察结果，不重复验收项编号。
- **用户场景与用例**：只写影响设计的典型场景；已知时补充用户类型、访问量、数据规模、实时性和缓存更新要求。
- **名词解释**：仅定义容易混淆或本次新增的业务与技术术语。
- **影响范围**：列出受影响的功能、用户、权限、查询方式、数据、接口、第三方和运行环境；范围很大时保留典型类别。

### 业务流程

描述用户或系统完成目标的主流程和关键异常分支。页面跳转、跨服务调用或状态流转难以用短文本表达时使用 Mermaid；图后写明边界和结论。

### 实现方式

- **总体设计**：说明系统边界、核心链路、关键决定、复用点以及调整前后差异。调研产生多种可行方案时，用表格比较成本、效果、限制和风险，并只保留最终选择。
- **前端**：写明新增或变化的页面、区域和交互；将按钮、输入、页面跳转映射到接口或平台能力，说明输入限制、文件处理、富文本、跨端跳转和埋点中实际命中的部分。
- **后端**：说明承担关键逻辑的服务或模块，以及事务、并发、批处理、定时任务、消息队列、新服务和第三方集成中实际命中的部分。模块名称可以保留，源码路径和符号不进入正文。
- **接口设计**：写明调用方、方法、URL、鉴权、请求与响应字段、类型、必填和约束、错误语义，以及分页、幂等、限流、缓存、超时、重试和回调校验中实际命中的部分。字段较多时使用 Markdown 表格；接口契约不能只用截图表达。
- **数据库设计**：说明新增或变化的表、字段、索引、约束和关系。关系复杂时使用 Mermaid ER 图；涉及结构变化时在正文给出评审所需 DDL、锁与容量风险、事务边界、验证 SQL 和回滚方式。
- **历史数据处理**：说明回填或修正范围、批次与顺序、在线业务和第三方影响、校验、停止及回滚方法。没有历史数据变化时可省略。
- **权限与安全**：说明服务端可信身份、授权和数据范围，敏感数据在存储、传输、响应、展示和日志中的保护，以及防越权、防滥用和内容安全中实际命中的部分。
- **配置、资源与联调**：列出环境变量名、配置中心项、云资源、第三方凭据获取方式和联调依赖，说明环境差异、申请前置、负责人和费用；不得记录凭据值。
- **可观测性**：说明正常与异常链路需要的日志、指标、追踪、告警和审计，以及第三方失败、数据异常和资源接近容量阈值时的触发与处置。
- **技术关键点与解决方案**：只汇总无法自然归入前述小节的关键技术问题、取舍和解决方案，避免重复。

### 异常方案

覆盖会改变设计的极端输入、依赖不可用、第三方超时或限流、部分成功、数据异常和资源不足。说明降级、重试、幂等、补偿、告警和人工处置中实际采用的机制，以及功能如何恢复。

### 发布与验证

按依赖顺序说明代码、接口、配置、云资源和数据变更如何发布，兼容窗口和灰度如何控制，每一步如何验证、停止和回滚。测试策略覆盖已确认行为以及实际命中的契约、权限、迁移、性能、容量、缓存一致性和第三方故障风险。

### 风险与待确认问题

真实但暂时无法消除的风险写明影响、触发条件、缓解措施、负责人和处理时点。需要外部决定的问题写明确认方和期望确认时点；能从代码、已有决定或已确认需求得到答案的问题不放在这里。

## 专项扫描

逐项判断是否命中；命中时把结论写入对应章节，不复制本清单。

| 场景 | 需要形成的设计结论 |
| --- | --- |
| 导入、导出、批量处理、统计或看板 | 数据量、关键查询、同步或异步、预计耗时、并发限制、慢查询与在线业务影响 |
| 视频、文档、压缩包或大图片 | 类型、大小和数量、存储位置与期限、命名与访问、上传下载性能、CPU/内存/磁盘、权限、限流和费用 |
| 高并发、大数据量或实时数据 | 容量与延迟目标、缓存更新、一致性、热点、资源预算、限流和扩容触发条件 |
| 埋点上报 | 事件、触发时机、参数、去重和归属；前后端工作量与业务接口分开说明 |
| 手机号、身份证号、卡号、地址等敏感信息 | 可信数据源、服务端权限、最小返回、存储与传输保护、响应脱敏、页面展示和日志保护 |
| 金额、交易、进度或比例等高精度数据 | 数据来源、计算与舍入规则、边界值、权限和准确性校验 |
| 新服务、云能力、定时任务或消息队列 | 解决的问题、架构变化、接入与维护成本、权限、容量、故障处置和费用 |
| 第三方调用或回调 | 能力边界、鉴权与验签、限流、并发、超时、重试、幂等、降级、回调校验和告警 |
| API 或小程序常用能力 | 分页上限、实时或缓存、数据最小化、防越权、防滥用和反爬取 |
| 富文本、H5、小程序或第三方组件跳转 | 内容安全、性能、权限、参数校验、失败返回路径和跨端兼容 |

## 评审收敛

1. **核心技术视角**：先检查数据库与历史数据、新服务、架构调整、核心逻辑、容量、风险和费用。
2. **前后端协作视角**：再检查页面交互、接口字段、状态、异常约定和联调方式，解决阻塞开发的问题。
3. **项目交付视角**：最后由产品、测试、运维或管理角色按职责检查需求反讲、测试边界、发布回滚、监控告警、资源和费用。

缺少对应角色时仍按三个视角自检。未解决的阻塞项不能进入实施；非阻塞风险保留影响、负责人和处理时点。

## Markdown 约定

- H1 使用可识别的功能或迭代名称；名称未知时保留“技术方案”。
- 单任务方案保留内部模板全部 H2，H3 按实际内容保留；迭代总方案使用汇总模板，并可以删除空白 H2 和 H3。
- 接口字段、错误码、配置差异和方案比较使用表格；JSON、DDL、SQL 和交互示例使用带语言标记的代码块。
- 图只用于复杂关系、流程、时序、状态或 ER 模型，不能替代字段、规则、容量、异常和回滚说明。
- 使用实际服务、模块、页面、表、字段、接口和配置项名称。单任务方案可以附内部路径和代码符号作为证据；迭代总方案不得用内部引用、外部链接或模糊占位语代替方案内容。
