# 维护项目专业术语与关键决策

## 上下文契约

必读：根目录 `CONTEXT.md` 和用户请求。

按需读取：当前任务的 `task.json`、`decisions.md`、相关代码和文档，以及 `CONTEXT.md` 关键决策索引指向的相关 ADR。

初始禁止：无关任务、全部目标仓库、索引中与当前主题无关的 ADR和全部项目知识。

输出：更新后的 `CONTEXT.md` 和必要的根目录 `adr/*.md`。

## 流程

1. 区分当前信息是专业术语、关键决定还是普通任务事实。普通范围、验收和临时实施选择留在任务 `decisions.md`；验证后的项目级事实写入 `project/index.md`，仓库事实写入 `project/repositories/<repo-id>.md`。完成：信息归属唯一。
2. 对照 `CONTEXT.md` 挑战含糊、冲突或一词多义的表达，并用具体场景和代码事实核对边界；不能从现有事实确定时再询问用户。完成：术语具有一个规范名称、明确含义和必要的避免用语。
3. 术语确认后读取 [专业术语与索引格式](references/context-format.md)，直接更新 `CONTEXT.md`。写入前重新读取文件和 Git 状态；存在来源不明的重叠修改时停止并让用户决定。完成：定义简短、无实现细节，现有术语和索引未丢失。
4. 只有决定同时满足“难以逆转”“脱离背景会令人意外”“存在真实取舍”时才创建 ADR。读取 [ADR 格式与门槛](references/adr-format.md)，展示标题、范围、摘要、决定和替代关系并取得明确确认。扫描 `adr/[0-9][0-9][0-9][0-9]-*.md`，以当前最大编号加一创建文件，同时更新 `CONTEXT.md` 索引。完成：ADR 和索引一致；不满足门槛的决定只留在任务记录。
5. 当代码、任务文档、术语或现有 ADR 冲突时显式指出，不静默选择。替代旧决定时同步更新新旧 ADR 状态和索引；约束消失时记录弃用理由。完成：当前有效决定可从 `CONTEXT.md` 直接识别，历史原因仍可追溯。

## 边界

- `CONTEXT.md` 只保存项目简介、专业术语和关键决策索引；不是需求、规格、实现说明、会议纪要或草稿。
- 根目录 `adr/` 保存一个逻辑项目共用的关键决策；仓库和模块只作为读取范围。
- 不创建额外 JSON 状态、受管元数据、revision 或锁协议；Git 负责历史、并发冲突和恢复。
- 不在长期记忆中保存密钥值、个人敏感信息或仅对本机有效的私有路径。
